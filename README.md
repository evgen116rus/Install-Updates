# 🪟 Install-Updates — последовательная установка обновлений Windows (.msu)

Оконная утилита на PowerShell для установки автономных пакетов обновлений Windows (`*.msu`) **по очереди, в заданном порядке, с перезагрузкой после каждого обновления** и автоматическим продолжением после входа в систему.

> [!IMPORTANT]
> Скрипт устанавливает системные обновления и перезагружает компьютер. Сохраните открытые документы и, если это важная машина, сначала проверьте работу на тестовой системе или создайте точку восстановления/резервную копию.

## 📦 Состав

| Файл | Назначение |
| --- | --- |
| **`Install-Updates.ps1`** | Сам скрипт (окно со списком обновлений) |
| **`Start-Install-Updates.cmd`** | Запуск скрипта в обход политики выполнения PowerShell (двойной клик) |

При работе рядом со скриптом создаются служебные файлы:

| Файл | Назначение |
| --- | --- |
| `update_queue.txt` | Очередь ещё не установленных обновлений (нужна для продолжения после перезагрузки) |
| `update_install.log` | Журнал работы |

А также временная задача планировщика **`MsuSequentialInstaller`** — она запускает скрипт после входа в систему и удаляется, когда очередь закончилась.

## ✅ Требования

- Windows 10/11 со штатным Windows PowerShell 5.1
- Права администратора (скрипт сам запросит повышение через UAC)
- Файлы `*.msu` лежат **в той же папке, что и скрипт**
- Служба «Центр обновления Windows» не должна быть отключена (без неё `wusa.exe` обычно не работает)

## ⚙️ Использование

1. Скопируйте `Install-Updates.ps1` и `Start-Install-Updates.cmd` в папку с файлами `*.msu`.
   Лучше использовать **локальную папку** (например, `C:\Updates`), см. [FAQ про сетевые папки](#установка-из-сетевой-папки--сетевого-диска).

2. Запустите **`Start-Install-Updates.cmd`** (двойной клик) и подтвердите запрос UAC.

3. В открывшемся окне:
   - снимите/поставьте галочки у нужных обновлений;
   - кнопками **`▲ Вверх`** / **`▼ Вниз`** выставьте порядок установки (выделите строку и сдвиньте её);
   - при необходимости нажмите **`Проверить новые файлы`**, если вы добавили `*.msu` в папку после запуска.

4. Нажмите **`Начать установку`** и подтвердите итоговый порядок.

5. Дальше всё происходит автоматически:
   1. устанавливается первое обновление из очереди;
   2. появляется обратный отсчёт **30 секунд** до перезагрузки (кнопка **`Отмена`** отменяет перезагрузку);
   3. компьютер перезагружается;
   4. после входа в систему окно открывается само, через **20 секунд** (кнопка **`Отмена`** отменяет автопродолжение) начинается установка следующего обновления;
   5. так повторяется, пока очередь не закончится. После последнего обновления выполняется финальная перезагрузка, а задача автозапуска удаляется.

> [!NOTE]
> Для продолжения после перезагрузки нужно **войти в систему под той же учётной записью**, из-под которой запускали скрипт. Если вход защищён паролем и автовход не настроен, установка дождётся, пока вы войдёте.

## ℹ️ Окно программы

### Список обновлений

| Колонка | Что показывает |
| --- | --- |
| **№** | Порядок установки (сверху вниз) |
| **Файл** | Имя `.msu` файла |
| **KB** | Номер обновления, найденный в имени файла |
| **Размер** | Размер файла |
| **Статус** | Текущее состояние (см. ниже) |

Устанавливаются только строки **с галочкой**, строго сверху вниз.

### Статусы

| Статус | Значение |
| --- | --- |
| `Не установлено` | Обновление не найдено в системе, по умолчанию отмечено галочкой |
| `Уже установлено (…)` | Обновление найдено в системе (в скобках — источник), серый цвет, галочка снята |
| `Ожидает` | Строка в очереди после перезагрузки |
| `Установка...` | Идёт установка (синий) |
| `Установлено (нужна перезагрузка)` | Успешно, будет перезагрузка (зелёный) |
| `Уже установлено` | `wusa` сообщил, что обновление уже есть, перезагрузка не нужна |
| `Не применимо к этой системе` | Обновление не подходит этой системе, пропущено без перезагрузки |
| `ОШИБКА 0x…` / `ФАЙЛ НЕ НАЙДЕН` | Ошибка, очередь остановлена (красный) |

### Кнопки

| Кнопка | Действие |
| --- | --- |
| **`▲ Вверх` / `▼ Вниз`** | Перемещение выделенного обновления в очереди |
| **`Выбрать все` / `Снять все`** | Отметить/снять все галочки |
| **`Проверить новые файлы`** | Пересканировать папку: новые `*.msu` добавляются в конец списка, исчезнувшие файлы убираются, порядок и галочки остальных не меняются |
| **`Начать установку`** | Запустить установку отмеченных обновлений |
| **`Отмена`** | Активна только во время обратных отсчётов (перед перезагрузкой и перед автопродолжением). Прервать уже идущую установку `wusa` нельзя |

Закрыть окно во время установки нельзя — программа попросит дождаться завершения.

## 🔎 Как определяется, что обновление уже установлено

Стандартная команда `Get-HotFix` показывает неполный список (часто не видит накопительные обновления), поэтому скрипт объединяет три источника:

1. **Журнал Центра обновлений Windows** — то же, что в «Параметры → Центр обновления Windows → Журнал обновлений». Учитываются успешные установки; если обновление потом было удалено, оно считается неустановленным.
2. **Пакеты обслуживания (CBS) в реестре** — полностью установленные пакеты с номером KB в имени.
3. **`Get-HotFix`** — для полноты.

Определение по KB-номеру из **имени файла** (`...KB5124008...msu`). Если в имени файла KB нет, обновление всегда считается неустановленным.

> [!TIP]
> Если обновление ошибочно осталось отмеченным, ничего страшного: `wusa` вернёт «уже установлено», и программа без перезагрузки перейдёт к следующему.

## 🔢 Порядок установки по умолчанию

Файлы выстраиваются по списку `$defaultOrder` в начале скрипта:

```
KB5124008 → KB5129195 → KB5124010 → KB5127648 → KB5121794 →
KB5134133 → KB5127936 → KB5132061 → KB5132057
```

Файлы с другими KB идут **после** них, по алфавиту. Чтобы изменить порядок по умолчанию, отредактируйте массив `$defaultOrder` в `Install-Updates.ps1`. Вручную порядок меняется кнопками **`▲ Вверх` / `▼ Вниз`** прямо в окне.

> [!WARNING]
> Порядок установки важен: например, обновление стека обслуживания (SSU) обычно нужно ставить раньше накопительного. Ошибка `0x800F0823` чаще всего указывает как раз на нарушенную последовательность или отсутствие нужных предварительных обновлений.

## 🧾 Как обрабатываются результаты установки

Установка выполняется командой `wusa.exe "<файл>" /quiet /norestart`. Результат определяется по коду возврата:

| Код | Что делает скрипт |
| --- | --- |
| `0`, `3010` (`0x00000BC2`), `0x00240005` | Успех → обратный отсчёт и **перезагрузка** |
| `0x00240006` | Уже установлено → пропуск, без перезагрузки |
| `0x80240017` | Не применимо к системе → пропуск, без перезагрузки |
| любой другой | Ошибка → очередь **останавливается**, автозапуск отключается |

При ошибке сбойное обновление остаётся **первым** в сохранённой очереди. После устранения причины запустите скрипт снова — он предложит продолжить незавершённую очередь.

## ☑️ Распространённые вопросы и проблемы

### Установка остановилась с ошибкой

- Откройте `update_install.log` — там записан код возврата `wusa.exe` (например, `0x800F0823`).
- Устраните причину (недостающие предварительные обновления, неверный порядок, повреждённый файл).
- Запустите **`Start-Install-Updates.cmd`** снова и ответьте **«Да»** на предложение продолжить очередь, либо **«Нет»**, чтобы сбросить её и начать заново.

### После перезагрузки окно не появилось

- Убедитесь, что вы вошли в систему под той же учётной записью, из-под которой запускали скрипт.
- Проверьте, что задача `MsuSequentialInstaller` есть в «Планировщике заданий» (`taskschd.msc`).
- Папка со скриптом должна быть доступна сразу после входа в систему (см. следующий пункт).
- Если ничего не помогло, просто запустите `Start-Install-Updates.cmd` вручную — программа найдёт сохранённую очередь и предложит продолжить.

### Установка из сетевой папки / сетевого диска

После перезагрузки скрипт запускается с повышенными правами, а подключённые сетевые диски (`I:\` и т. п.) в таком сеансе могут быть недоступны или подключиться не сразу. Кроме того, большие `.msu` надёжнее ставить с локального диска. **Рекомендуется скопировать папку с обновлениями и скриптом на локальный диск**, например в `C:\Updates` (без кириллицы и пробелов в пути).

### Я отменил перезагрузку

Задача автозапуска и очередь сохраняются. Перезагрузите компьютер вручную — после входа установка продолжится. Либо запустите скрипт снова и выберите продолжение очереди.

### Скрипт не запускается / ругается на политику выполнения

Запускайте через **`Start-Install-Updates.cmd`**. Если скрипт скачан из интернета, снимите блокировку:

```powershell
Unblock-File .\Install-Updates.ps1
```

### Вместо русских букв «кракозябры»

Файл `Install-Updates.ps1` сохранён в кодировке **UTF-8 с BOM** — Windows PowerShell 5.1 без BOM читает его неверно. Если редактируете скрипт, сохраняйте именно в «UTF-8 with BOM».

### Как полностью сбросить очередь и автозапуск

1. Удалите файл `update_queue.txt`.
2. Удалите задачу планировщика (PowerShell от имени администратора):

```powershell
Unregister-ScheduledTask -TaskName MsuSequentialInstaller -Confirm:$false
```

(или вручную в `taskschd.msc`).

### Почему перезагрузка после каждого обновления?

Так задумано: следующее обновление должно устанавливаться на уже «закрытую» перезагрузкой систему. Перезагрузка выполняется после каждого обновления, которое установилось успешно. Если обновление уже было установлено или не подходит системе, оно пропускается без перезагрузки.

## 🗒️ Служебная информация

- Журнал `update_install.log` дописывается при каждом запуске. Формат строки: `[дата время] сообщение`.
- Для работы с планировщиком используются командлеты `Register-ScheduledTask` / `Unregister-ScheduledTask`.
- Скрипт распространяется «как есть», без гарантий. Используйте на свой риск.
